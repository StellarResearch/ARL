Simulation Dynamics

3-DOF Kinematics vs. 6-DOF Rigid-Body Dynamics

ARL provides dual simulation environments designed for different phases of research: fast point-mass exploration and rigid-body quadrotor attitude verification.

Simulation Dimension 3-DOF Kinematic Drone 6-DOF Rigid-Body Quadrotor
Physical Model Point-mass translational kinematics with aerodynamic drag damping. Full rigid-body quadrotor with rotational inertia matrix, motor thrust curves, and reaction torques.
State Vector 29 Dimensions (Normalized pos, vel, goal, rel_goal, dist, 16-ray LiDAR). 36 Dimensions (Pos, vel, unit quaternion attitude [qw, qx, qy, qz], body angular rates [p, q, r], goal, rel_goal, dist, 16-ray LiDAR).
Action Vector 3 Dimensions: Continuous Cartesian accelerations [ax, ay, az] ∈ [-1.0, 1.0]³. 4 Dimensions: Continuous individual motor thrust commands [u1, u2, u3, u4] ∈ [-1.0, 1.0]⁴.
Attitude Representation Not modeled (translational point-mass). Unit quaternion $\mathbf{q}$ with body-to-world rotation matrix $R(\mathbf{q})$. Continuous re-normalization prevents numerical drift.
Numerical Integration Semi-implicit Euler stepping ($\Delta t = 0.1\text{s}$). Runge-Kutta 4th-order (RK4) integration with 5 substeps ($\Delta t_{\text{sub}} = 0.01\text{s}$).
Supported Algorithms Stable-Baselines3 PPO, SAC, and Random Action Baseline. Stable-Baselines3 PPO, SAC, and Random Action Baseline.
Primary Use Case Fast prototyping, rapid hyperparameter tuning, curriculum learning. Attitude stability verification, high-fidelity control, torque coupling research.

  • Standard Farama Gymnasium interface
  • 30m × 30m × 15m arena with obstacle clearance
  • Dynamic wind disturbance fields (steady & gusts)
  • Deterministic seeding with reproducible schedules
  • Strict collision and boundary termination logic

  • 16-Ray spherical LiDAR (Fibonacci sphere distribution)
  • Analytical ray-sphere and ray-box intersections

  • Standardized checkpoint serialization & inspection
  • Extensible algorithm registry for custom agents

  • Automated comparison against untrained baseline

Deployment

Quick-Start Installation (Linux)

Setup AdaptiveRL in a clean Python virtual environment and run tests in under two minutes.

1

Clone Repository & Create Virtual Environment

bash 
git clone https://github.com/StellarResearch/ARL.git
cd ARL
python3 -m venv .venv
source .venv/bin/activate
2

Install Dependencies & Execute Test Suite

bash 
pip install --upgrade pip
pip install -e ".[all]"
pytest tests/
3

Train a Policy & Run Evaluation

bash 
adaptive-rl train --config configs/drone_ppo_demo.yaml
adaptive-rl evaluate --config configs/drone_ppo_demo.yaml --compare-random
4

Launch Flight Deck GUI

bash 
adaptive-rl gui
Integrity & Scope

Technical Limitations & Safety Boundaries

Transparent research boundaries to prevent misrepresentation of simulation fidelity or hardware readiness.

Theoretical Simulation Scope

⚠️
No Physical Hardware Validation: ARL is an algorithmic reinforcement-learning research tool. It has not been benchmarked on physical drone flight hardware (e.g. Crazyflie, Pixhawk, or PX4).
⚠️
Aerodynamic Approximations: The 6-DOF environment models rigid-body dynamics, linear drag damping, and motor thrust curves. It does not model blade flapping, ground effect, or motor thermal lag.
⚠️
Idealized Spherical LiDAR: Analytical raycasting computes exact mathematical sphere and box intersections without simulating laser atmospheric backscatter, fog attenuation, or material surface reflectance.

Intended Operating Environment

🛡️
Non-Flight-Critical Research: Intended solely for academic experimentation, algorithm comparison (PPO vs SAC vs Planners), and curriculum reinforcement learning research.
🛡️
Sim-to-Real Prerequisite: Direct physical flight deployment requires adding domain randomization (gust turbulence, sensor delay, payload variance) and integration with standard robotics middleware (ROS 2 / Gazebo).
🛡️
No Hardware Override: ARL policies must never be connected directly to motor electronic speed controllers (ESCs) without hardware fail-safes and manual pilot overrides.

Slide 02 // Problem Formulation

Reactive 3D Spatial Navigation

Traditional geometric path planners (such as A* and RRT*) depend on complete static maps and high-overhead replanning. ARL evaluates reactive, model-free neural policies that map local distance rangefinding directly to continuous motor commands.

  • Task: Navigate a bounded 30m × 30m × 15m volume towards an unknown target waypoint.
  • Obstacles: Procedural spherical obstacles placed with collision clearance guarantees.
  • Perception: 16-ray spherical rangefinder tracking local spatial proximity.
Slide 03 // Dynamics Comparison

Point-Mass vs. Rigid-Body Quadrotor

ARL strictly separates point-mass translational kinematics from rigid-body quadrotor attitude dynamics.

  • 3-DOF: Semi-implicit Euler integration, continuous Cartesian acceleration commands, 29-D state vector.
  • 6-DOF: Runge-Kutta 4th-order (RK4) integration with 5 substeps, unit quaternion attitude kinematics, 4 individual motor thrust commands, 36-D state vector.
Slide 04 // Perception Architecture

16-Ray Spherical LiDAR Sensor

The simulated sensor projects 16 unit vectors uniformly distributed across a unit sphere using the golden-ratio Fibonacci spiral.

  • Closed-form geometric ray-sphere and ray-box intersection algorithms.
  • Zero-delay distance calculation bounded to 20.0 meters maximum range.
  • Configurable sensor noise, dropout probability, and blind-zone radii.
Slide 05 // Algorithm Suite

Continuous-Action PPO & SAC

Implemented on top of Stable-Baselines3 and PyTorch with modular configuration files.

  • PPO: Clipped surrogate loss ($\epsilon = 0.2$), GAE advantage estimation ($\lambda = 0.95$), Gaussian policy outputs.
  • SAC: Maximum entropy actor-critic with twin Q-critics and soft target updates for robust continuous control.
Slide 06 // Reward Formulation

Multi-Objective Reward Shaping

Reward formulation balances goal attraction, collision avoidance, and flight efficiency: 

R_t = 2.0 * (d_{t-1} - d_t)      # Progress reward
    - 0.05                      # Timestep penalty
    - 0.01 * ||a_t||²           # Actuation effort penalty
    + 100.0 (if d_t <= 1.5m)    # Goal arrival reward
    - 100.0 (on collision)      # Obstacle / boundary penalty
Slide 07 // Empirical Results

Measured Policy Performance

Rigorous benchmarking under deterministic seeds:

  • Random Baseline: 100% collision rate, -101.24 mean return.
  • Trained PPO Policy: 35% collision rate, 65% survival rate, -3.34 mean return.
  • Clutter Sensitivity: Collision frequency scales monotonically across 4, 6, and 8 obstacles.
